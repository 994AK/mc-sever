# Guild Project Daily Activity Rules

## Summary

这是公会项目日活体系的 v1 运营规则。第一周先跑小规模试运行：1 个官方项目、1 个公会提案名额、人工确认参与名单、奖励只给荣誉展示和少量非战斗补给。

---

## Week 1 Setup

试运行周期：2026-06-09 到 2026-06-16。

默认节奏：

| 时间 | 动作 | 负责人 |
| --- | --- | --- |
| 周二 | 发布官方项目和公会提案入口 | 管理 |
| 周三 | 截止公会提案，确认本周提案项目 | 管理 |
| 周四到周日 | 玩家参与建设、采集、维护和测试 | 公会 / 项目负责人 |
| 周日晚上 | 项目负责人提交成果和参与名单 | 项目负责人 |
| 周一 | 管理验收、发奖励、更新展示 | 管理 |

如果第一周还没有稳定公会，可以允许 2 人以上临时项目小队报名。临时小队只用于试运行，不默认获得长期公会权益。

## In-Game Commands

玩家不用阅读本文档也能从游戏内进入体系：

| Command | Use |
| --- | --- |
| `/projects` | 查看本周官方项目、公会提案位、参与方式和相关入口 |
| `/daily` | 查看每日/每周 Quests 任务，并列出可接任务 |
| `/guild` | 查看 BetterTeams 公会/小队命令和边界 |
| `/proposal` | 查看公会项目提案模板 |
| `/projectrewards` | 查看允许和禁止奖励 |
| `/projectsubmit` | 项目负责人提交验收时使用的模板 |
| `/menu` | 快捷菜单里有“本周项目”“每日任务”“公会小队”入口 |

插件边界：

- BetterTeams 只用于公会身份、成员组织和队聊；队伍传送、队伍银行、队伍箱子、击杀加分、PvP 切换和 scoreboard team 接管已关闭或权限禁止。
- Quests 只用于轻任务入口：每日项目签到、每周项目墙协助、每周红石材料协助。任务完成不自动算公会贡献。
- 贡献仍由项目负责人名单、可见成果、截图/坐标/物资记录和管理验收确认。

## Week 1 Projects

### Official Project: Main Hub Project Board

项目编号：`W1-O1`

目标：在主城或出生点附近建立“本周项目墙 + 公会荣誉墙”的第一版，让玩家进服后知道这周能做什么、完成后谁被记录。

公共价值：

- 让日活体系有游戏内入口，不只停留在群公告。
- 给后续每周项目留下展示位置。
- 让参与公会能被看见。

推荐任务：

- 建一个小型公告墙或公告亭。
- 放置“本周官方项目”“本周公会提案项目”“已完成项目”“参与名单”四个区域。
- 写清项目报名方式：找管理、项目负责人，或用 `/helpop 内容`。
- 预留至少 4 周的项目记录空间。

验收标准：

- 玩家从出生点或主城路线能找到项目墙。
- 项目墙能显示本周两个项目、负责人、截止时间和参与名单。
- 告示内容简短清楚，不遮挡公共道路或已有建筑。
- 不使用 WorldEdit 或创造权限作为普通玩家奖励。

默认奖励：

- 参与者：`W1 建设参与` 记录 + 1 份轻补给。
- 核心成员：项目墙署名 + 1 周展示称号候选。
- 公会：公会名进入第一周荣誉墙。

### Guild Proposal Slot: Public Redstone Supply Pool

项目编号：`W1-G1`

默认提案：如果没有公会主动提交更合适的公共项目，本周公会提案位默认跑“公共红石材料池 v1”。

目标：建立一个小型公共红石材料补给点，服务后续生电项目、线路维护和新手学习。

公共价值：

- 红石服需要材料协作，公共材料池能减少重复劳动。
- 公会可以通过捐赠、整理、标识和维护体现贡献。
- 后续生电项目可以从这里领取基础材料。

推荐任务：

- 建一个不大的公共箱子区，优先放在主城、红石教学区或公共仓库旁。
- 分类标识红石粉、红石火把、中继器、比较器、漏斗、活塞、粘性活塞、侦测器、铁、石英和木材。
- 每类材料只要求起步量，不追求塞满。
- 写清“公共项目优先使用，禁止整箱搬空”。

验收标准：

- 箱子区能正常访问，位置不占用私人领地。
- 至少 6 类红石常用物资有标识和少量库存。
- 有 1 名项目负责人负责每周检查一次。
- 管理确认参与名单和材料来源合理。

默认奖励：

- 参与者：`W1 红石材料池参与` 记录 + 1 份轻补给。
- 负责人：材料池署名 + 下周公会提案优先权候选。
- 公会：公会名进入本周公会项目记录。

## Guild Proposal Template

公会提案必须先过管理审核，审核通过才算本周公会提案项目。

```text
【公会项目提案】

公会 / 小队名：
提案人：
项目名：
项目类型：
项目地点：
预计参与人数：
预计完成时间：

这个项目对服务器有什么公共价值：
<说明它服务谁，不只是服务自己家>

需要管理协助：
<例如设置公告牌、确认公共地点、最后验收>

完成后如何验收：
1. <可见成果>
2. <参与名单>
3. <截图 / 坐标 / 物资记录>
```

拒绝计入的提案：

- 私人基地装修，没有公共价值。
- 单纯囤资源，成果不开放给公共项目。
- 要求奖励飞行、神装、创造、WorldEdit 或管理权限。
- 明显会造成卡顿、破坏红石生电规则或影响公共区域。
- 大范围圈地、占路、占村庄、占地狱门或影响别人领地。

## Reward Table

奖励按“确认参与”发，不按方块数量、在线时长或捐赠数量无限叠加。

| 档位 | 条件 | 个人奖励 | 公会奖励 |
| --- | --- | --- | --- |
| 参与 | 参与建设、采集、整理、测试或维护，并被负责人写入名单 | 参与记录 + 1 份轻补给 | 计入项目参与名单 |
| 有效贡献 | 完成一个明确子任务，例如一段路、一组箱子分类、一批材料整理或一轮机器测试 | 参与记录 + 项目署名候选 + 1 份轻补给 | 公会名进入项目记录 |
| 核心贡献 | 承担项目负责人、设计、协调、验收准备或关键问题修复 | 负责人署名 + 1 周称号候选 | 公会展示墙优先位置 |
| 项目完成 | 项目整体通过验收 | 全员项目记录 | 公会获得本周完成记录 |

轻补给建议从下面选 1 份，不叠加刷：

| 补给 | 数量 | 适用场景 |
| --- | --- | --- |
| 面包或熟食 | 16-32 | 新手、建设、跑图 |
| 火把 | 32-64 | 挖矿、修路、公共区域照明 |
| 普通烟花火箭 | 8-16 | 赶路和庆祝，不作为飞行奖励核心 |
| 经验瓶 | 8-16 | 修补工具的小反馈，不大量发 |
| 普通建材 | 1-3 组 | 项目继续建设，不给稀缺资源 |
| 纪念书 / 命名纸 | 1 | 记录参与，不产生战力 |

可展示奖励：

| 奖励 | 周期 | 说明 |
| --- | --- | --- |
| 项目墙署名 | 长期 | 写项目名、公会名、参与者 |
| 公会荣誉墙 | 每周更新 | 展示本周完成项目 |
| 临时称号 | 7 天或到下周结算 | 例如 `[筑路者]`、`[红石助手]`、`[主城建设者]` |
| 提案优先权 | 下周有效 | 核心贡献公会下周优先获得提案审核 |
| 公共 warp 申请资格 | 管理审核后生效 | 只给确有公共价值的地点，不自动发 |

禁止奖励：

- 免费 `/fly`、长期飞行或飞行充能。
- 钻石/下界合金神装、高等级附魔装备、高效率工具。
- WorldEdit、创造、CoreProtect、强制传送、管理命令。
- 大量铁、钻石、绿宝石、下界合金或其他会冲击生存经济的资源。

## Review Checklist

项目验收时用这张表，不需要追求复杂自动化。

| 项目 | 检查项 | 结果 |
| --- | --- | --- |
| 基本信息 | 项目编号、项目名、负责人是否明确 | 通过 / 补充 |
| 公共价值 | 成果是否服务公共建设、资源、生电、建筑、新手或秩序 | 通过 / 不通过 |
| 地点安全 | 是否避开私人领地、公共道路、村庄、地狱门和他人建筑 | 通过 / 整改 |
| 完成标准 | 发布时写的验收标准是否达成 | 通过 / 部分通过 / 不通过 |
| 参与名单 | 名单是否由负责人提交，是否有明显争议 | 通过 / 待确认 |
| 证据 | 是否有截图、坐标、物资记录、现场成果或管理观察 | 通过 / 补证 |
| 奖励边界 | 奖励是否只包含荣誉、展示、记录和少量非战斗补给 | 通过 / 调整 |
| 展示更新 | 项目墙、公告或公会荣誉墙是否更新 | 完成 / 待处理 |

验收结论只用三种：

- **通过:** 计入本周项目，发奖励并更新展示。
- **部分通过:** 记录已完成部分，要求补齐后再发完整公会奖励。
- **不通过:** 不计入体系，可以作为私人项目保留。

## Admin Operating Rules

- 每周项目宁少勿多，默认 2 个项目足够。
- 每个项目都要有负责人，否则不开放报名。
- 奖励先按记录和展示走，补给只是当天反馈。
- 有争议时先补证，不在聊天里争吵贡献多少。
- 公会提案必须证明公共价值，不能把私人基地建设包装成公共项目。
- 第一周结束后只复盘三件事：有没有人参与、管理审核累不累、奖励有没有破坏生存平衡。
